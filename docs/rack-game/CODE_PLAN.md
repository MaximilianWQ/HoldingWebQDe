## 0. Главное: работаем в корпусе `v-`, а не в «Атласе»

**Боевую главную рисует `src/components/vps/Home.tsx`.**
`src/components/atlas/AtlasHome.tsx` — мёртвый код.

Проверено напрямую:

* `src/app/page.tsx:7` — `import HomeView from "@/components/vps/Home";`,
  `:29` — `return <HomeView referralCode={params.ref} />;`
* `AtlasHome` не импортирует ни один живой файл: единственный импорт —
  `src/app/lab/hero/page.tsx:4`, а `src/app/lab/` исключена из гита
  (`.git/info/exclude`) и из выкладки (`.railwayignore`).

Вместе с ним мертвы: `home-v5.css` (`h5-`), `home-hero.css`,
`home-map.css`, `home-mobile.css`, `atlas-mobile.css` (токены `--m-*`),
`HeroSchema`, `PresenceSchema`, `LaptopScrub`, `SmoothScroll`/Lenis.

**Раздел CLAUDE.md «Главная, редакция 5» описывает именно этот мёртвый
корпус** — опираться на него при встройке нельзя.

## 3. Образцы, которым следовать

### Сервер → клиент
Канон `VShell` → `VHeader`: оболочка серверная, читает язык один раз и
отдаёт клиентской части ГОТОВЫЕ строки. Второй канон — `FaqAccordion`:
клиент получает уже собранные вопросы, включая React-узлы со ссылками
(`rich()` разворачивается на сервере).

Соответствие «массив в коде ↔ массив в словаре» — `WhyBento.tsx`:
неязыковое (иконка, тон, картинка, высота в U) лежит в коде, подпись
приходит из словаря. **Для игры безопаснее ключ у каждого модуля
(`t.modules[m.id]`), а не индекс** — см. грабли №6.

### Клиентская часть
```tsx
"use client";
import { fill } from "@/lib/text/fill";   // ← ТОЛЬКО отсюда, НЕ из "@/i18n"
```

### Разметка и движение
Приём образцового (хоть и мёртвого) `PresenceSchema` + `…Motion`:
живой слой — крошечный клиентский компонент, который рендерит
`<span hidden>` и находит хозяина через `closest()`; значение пишется раз
в кадр через rAF в CSS-переменную, перерисовки React нет; вне кадра —
`IntersectionObserver` ставит `data-paused`; на грубом указателе слушатель
не ставится вовсе.

У нас правило чуть иное: игра без JS играть не может, поэтому доска
клиентская целиком — но текст и картинки получает пропсами, а её
**стартовое состояние обязано быть осмысленной картинкой само по себе**.

### Картинки
`next/image` в проекте не используется нигде. Везде обычный `<img>` с
явными `width`/`height`, `loading`, `decoding="async"`, при наборе —
`srcSet`/`sizes` (образец — постер `HeroGL`).
**`draggable={false}` обязателен** (образец — `IosPhone.tsx`): без него
браузер запускает системный drag картинки и свой жест перестаёт работать.

Бюджет веса — по замеру 32 сайтов (`research/06_RENDERS_2027.md`):
медиана предмета ≈130 КБ, Yandex Cloud 34 КБ. **Весь набор модулей должен
уложиться в эту медиану суммарно.**

## 6. Грабли, оплаченные раньше

1. **Мёртвый корпус.** Раздел, написанный в `atlas/`, на сайте не
   появится (см. §0).
2. **Оба словаря в браузере.** Клиент, импортирующий что угодно из
   `@/i18n`, тянет `ru.ts` + `en.ts`: 240 КБ на 12 маршрутах, и 292 КБ в
   кабинете — через СЕРВЕРНЫЙ `TrafficCards`, которого рисует клиентский
   родитель. Правило шире, чем кажется. Проверка после сборки: строки из
   `ru.ts` не должно быть ни в одном `.next/static/chunks/*.js`.
3. **`prefers-reduced-motion` здесь — выключатель, а не «помягче».**
   `vps.css`: `.v *, .v *::before, .v *::after { animation: none
   !important; transition: none !important; }`. Значит «модуль встал в
   слот» нельзя показывать ТОЛЬКО движением — состояние обязано читаться
   по разметке.
4. **Без JS страница обязана быть целой.** В корпусе `v-` нет костыля
   `.a-js`, поэтому ничего не прячем до гидратации. Аудит белых экранов
   13.09.2026 поймал ровно это.
5. **Кеш `/media` на неделю** (`next.config.ts`), файлы в `public/` не
   хешируются. Перерисовали модуль — **меняем имя файла** (прецедент
   `stage-1720.v3.webp`), иначе неделю висит старый кадр.
6. **`Dict = typeof ru` ловит забытый КЛЮЧ, но не длину массива.**
   Связка «массив в коде ↔ массив в словаре по индексу» разъедется молча.
7. **Пилот, уехавший на бой.** 21.09.2026 пилот первого экрана ушёл на
   Railway вместо локалхоста и был откачен тем же днём. Игра живёт в
   своей ветке, пока владелец не сказал «берём».
8. **Слова витрины.** «VPS-ускоритель» — про сервис; «выделенные
   серверы» и «VDS» — про железо, и никогда «VPS» про железо; слов «VPN»
   и «обход» нет; инженерных терминов нет. Подписи модулей — самое
   опасное место для срыва в жаргон.
9. **Доступность.** Игра не может быть только перетаскиванием: нужен
   путь с клавиатуры (кнопки с `aria-pressed`). Минимум 44 px на тап.
   Перед сдачей — 320/375/414/768/1024/1280/1440/1920.
10. **`.v-section + .v-section { padding-top: 0; }`** — вставка раздела
    меняет отступы у соседей; проверять стык сверху и снизу.
11. **Тяжёлое — не на путь прокрутки.** Рендеры декодируются заранее
    (`loading="lazy"` + запас по `IntersectionObserver`), а не в момент,
    когда раздел въезжает в кадр.

## 7. Мягкая прокрутка

`SmoothScroll` монтируется только из `AtlasShell`, а тот жив лишь в
`/admin` с `footer="compact"` → `work = true` → Lenis не поднимается.
**На боевом сайте Lenis не загружается нигде; массив `NESTED` трогать не
нужно.** Ленте деталей на телефоне хватит готового `Carousel` с родным
`scroll-snap`.

## 8. Наклон камеры: проверено склейкой (21.09.2026)

Спецификация деталей требовала снимать модули строго фронтально.
Проверено опытом, а не обсуждением: три модуля склеены из отдельных
кадров так же, как это сделает браузер, и сравнены с эталонным
рендером, где те же модули стоят в раме в самой сцене.

| Что меряли | Результат |
|---|---|
| Сдвиги мест | 126,228 / 42,076 / −42,076 px |
| Ошибка округления до целого пикселя | 0,228 / 0,076 / 0,076 px |
| Среднее расхождение с эталоном | 7,98 из 255 |
| Пикселей хуже 24 | 6,8 % кадра |
| Горизонтальный снос | 0,000 px |

Карта расхождений показывает, что вся разница лежит на КРЫШКАХ модулей
и на отсветах внутри рамы, то есть это разница освещения, а не разъезд
геометрии. Стык юнитов точный; верхний модуль закрывает крышку нижнего
сам, порядком отрисовки снизу вверх.

**Наклон оставлен.** На странице живёт склейка, а не эталон. Сделать
каждое сочетание модулей физически честным значило бы отрендерить все
сочетания — при пяти местах это 32 кадра вместо шести. Склейка всегда
сама себе согласована.

Два условия, без которых это ломается:

1. **Отрисовка строго снизу вверх.** Иначе крышка нижнего модуля
   окажется поверх лицевой панели верхнего.
2. **Одинаковая глубина `DEPTH` у всех модулей.** При разной глубине
   поворот камеры по горизонтали даёт разную ширину в пикселях, и
   стойка поедет. Настоящие глубины (сервер 751 мм против коммутатора
   409 мм) поэтому НЕ переносятся в сцену — глубина стилизована и одна
   на весь набор.
