# Atlas Secure — VPN Service Website

## Project Overview
Atlas Secure is a VPN selling website built with Next.js. Features: email-based auth with OTP codes, automatic VPN key generation via Xray UUID, 3-day free trial, multi-device support, referral program (cashback to balance, 10/25/45%), and Telegram integration (+7 days bonus).

## Tech Stack
- **Framework**: Next.js 16 (App Router)
- **Language**: TypeScript (strict mode)
- **Styling**: Tailwind CSS v4 with custom design tokens
- **Email**: Nodemailer (SMTP)
- **VPN Backend**: Xray (VLESS/VMess/Trojan) with UUID-based user management

## Environment Variables
See `.env.example`. Key groups:
- **SMTP_*** — email delivery (codes logged to console without config)
- **XRAY_*** — Xray server: domain, port, protocol, Reality keys
- **XRAY_PANEL_*** — optional panel API (3x-ui, Marzban)
- **SERVER_ACTIONS_ALLOWED_ORIGINS** — дополнительные домены для server
  actions входа. Next отклоняет действие, если Origin не совпадает с
  x-forwarded-host (за прокси Railway так и бывает): «Invalid Server
  Actions request», E80. Свои домены перечислены в `next.config.ts`.
  Новый домен сайта добавлять туда же, иначе «Получить код» падает.

Исходники 3D-рендеров (Blender) — `design/blender/`, описание в README там.

## Architecture

### Auth Flow
1. `POST /api/auth/send-code` → 6-digit OTP to email (10min TTL, 5 attempts max)
2. `POST /api/auth/verify-code` → verify code → create user with Xray UUID + VLESS key → session cookie
3. Redirect to `/dashboard`

### Xray Integration (`src/lib/xray.ts`)
- **UUID Generation**: Each user gets a unique Xray UUID on registration
- **Connection URIs**: Builds VLESS/VMess/Trojan URIs with Reality/TLS params
- **API Client Stub**: Interface ready for gRPC or panel API implementation
- **Config Builder**: Generate Xray config.json client entries

**TODO for production**: Implement `XrayApiClient` methods to actually add/remove users from the Xray server via gRPC or panel API.

### Design System — РЕДАКЦИОННЫЙ КОРПУС

> **Устарело (13.09.2026).** Корпуса graticule / pixel / brand удалены
> вместе с `graticule.css`, `graticule-home.css`, `brand.css` и
> компонентами `src/components/{graticule,brand,pixel}` (остались
> `pixel/BrandMark`, `pixel/Icon`, `pixel/SiteJsonLd`, `brand/BackToTop`,
> `brand/PageTransition`, `brand/scroll-top`). Весь сайт — «Атлас-издание»:
> токены в `:root` файла `src/app/atlas.css`, гарнитура — MTS Wide из
> `src/app/atlas-fonts.ts` (переменная на `<html>`), общий слой —
> `globals.css` (сброс, Tailwind, `.b-sr`, `.b-skip`, `.b-top`), поля
> форм — `px-forms.css` (только /business и /contact). Текст ниже —
> история решений, а не действующие правила.

Единственный источник значений — блок токенов `:root` в
`src/app/graticule.css`. Разбор восемнадцати сайтов креативных студий,
которым обоснованы приёмы: `research/03_AGENCY_TEARDOWN.md`.

**Корпус — бумага и краска.** Фон `--g-paper` `#FFFFFF`, чистый белый.
Не титановый, не кремовый, не «почти белый»: полутон между бумагой и
краской размывает обоих. Утопленная полоса `--g-paper-2` `#F2F2F0`
отличается ровно настолько, чтобы читаться полосой. `--g-vellum`
оставлен псевдонимом бумаги: **поднятой плоскости в системе нет** —
белое на белом не поднимается, и её роль перешла к линейке и к
инверсии.

**Краска — чистый чёрный.** `--g-ink` `#000000` (21,00:1),
`--g-ink-2` `#3D3D3D` (10,86:1), `--g-ink-3` `#6E6E6E` (5,10:1). Три
ступени, не четыре: четвёртая в прежней системе дважды не проходила
порог и её приходилось чинить. Тонированный графит выведен — он был
нужен, пока рядом стоял изумруд и спорил за тон.

**Цветом отмечено ТОЛЬКО ТО, ЧТО ИЗМЕРЕНО.** `--g-chart` `#0F1BD6`
(ультрамарин, 9,78:1 — проходит AAA даже в 13px). Им красятся: отклик,
снятый с устройства читателя; частота кадров; задержка до узла; длина
полосы канала. **Ни кнопка, ни заголовок, ни рамка, ни иконка цвет не
получают.** Главное действие набирается **инверсией** — чёрная плита,
белый текст; на чёрной плите финала инверсия переворачивается обратно.
Единственное исключение — кольцо фокуса: доступность важнее чистоты
правила.

Отсюда следствие: цвет на странице означает ровно одно, и позиция
бренда «измерено, а не заявлено» получает собственную краску. Писать
`color: var(--g-chart)` у элемента, который ничего не измеряет, —
ошибка того же класса, что и хекс в компоненте.

**Второй цвет привязан к материалу, а не к смыслу.** `--g-acid`
`#CBF52A` — кислотный лайм. Правило то же (цветом отмечено только
измеренное), но какой именно краской, решает контраст, а не вкус:
ультрамарин даёт 9,78:1 на бумаге и 2,15:1 на плите, лайм — 1,26:1 на
бумаге и 16,63:1 на плите. Каждый цвет читается ровно на одном
материале и невозможен на другом. На бумаге измеренное синее, на
чёрной плите измеренное кислотное. Обоснование замером 28 сайтов —
`research/04_COLOR_2027.md`: насыщенный акцент в отрасли укладывается
ровно в два семейства, и оба у нас теперь есть.

**Состояний-цветов почти нет.** Успех показывается набором, а не
цветом: зелёного в системе нет вовсе. Остались `--g-shoal` `#8A4B00`
(внимание, 6,25:1) и `--g-rock` `#C4001F` (ошибка, 6,24:1) — только
там, где ошибка обязана быть заметна мгновенно.

**Тени выведены из системы.** `--g-lift-1/2/3` равны `none`. На белой
бумаге поднимать нечего: глубину даёт линейка и инверсия, а мягкая
серая тень под каждой карточкой — тот самый признак SaaS-набора, от
которого уходим. Токены оставлены пустыми, чтобы не править всех
потребителей разом; новых обращений к ним быть не должно.

**Радиуса нет.** `--g-radius: 0px`. Прежние 2px были компромиссом
между «нулевой радиус — типовая широкоформатная вёрстка» и «12–16px —
кит карточек». В редакционном корпусе прямой угол это не приём, а
материал: полоса, линейка и плита углов не скругляют.

**Шрифт — суперсемейство Sofia Sans в двух ширинах**
(`src/app/fonts.ts`). Отобрано замером: из каталога Google Fonts взяты
все вариативные гротески с кириллицей (70 семейств), и у Sofia Sans
единственная ось веса 1–1000 при живых узких начертаниях того же
рисунка. `--g-display` (Sofia Sans Condensed) — только дисплейный
слой: первый экран, заголовки сцен, сумма, проценты, финальный призыв,
всегда прописными. `--g-family` (Sofia Sans) — весь остальной текст.
Моноширинной в системе нет.

**Заголовок выключен по ширине колонки.** Каждая строка получает свой
кегль так, чтобы встать ровно в ширину: отношение ширины к кеглю
измерено в браузере на живом шрифте и записано в `--gh-k-*`, кегль
равен `100cqw / k`. Ноль JS, ноль сдвига макета при загрузке шрифта.
Ни один из восемнадцати разобранных сайтов так не делает — там везде
рваный правый край. **Меняя текст заголовка, начертание или трекинг,
надо перемерить k** (скрипт замера — `research/03_AGENCY_TEARDOWN.md`),
иначе строка перестанет попадать в колонку.

Второе слагаемое в `min()` — потолок по высоте окна. Без него первый
экран вырастал до 1079px при окне 900 и приборная полоса уезжала под
сгиб. Кадр обязан помещаться в экран целиком: проверено 900/900,
800/800, 844/844.

**Первый экран держит четыре вещи и ни одной лишней:** заголовок в две
выключенные строки, выносок (четверть кегля, разрядка вместо сжатия,
прижат вправо — он намеренно рвёт ровный прямоугольник), одна строка
смысла с одним действием, приборная полоса из шести показаний. Двух
живых показаний в полосе — отклик и частота кадров — и они
единственные цветные.

**Рваная сетка.** Сцены стоят по колонкам неровно (`[data-col]`),
заголовок сцены свисает на колонку левее. Шаг колонки один на весь
корпус — `--gh-col`: 4 колонки до 720px, 8 до 1100px, 12 дальше.

**Сплошного каркаса колонок на всю высоту документа НЕТ и заводить
его нельзя.** Двенадцать волосяных линий во весь рост добавляли кадру
узлов, но ни одного объекта: лист читался как тетрадь в клетку, а
вместе с полем сигнала давал кашу. Линия делит содержимое там, где
действительно что-то делит.

**Поле сигнала** — `src/components/graticule/SignalField.tsx`,
материал первого экрана: около двух тысяч штрихов, которые
разворачиваются вслед за рукой. Появилось по замеру
(`research/05_MOTION.md`), а не по вкусу: у нас было 38–63 узла в
кадре против медианы 135 у двадцати референсов, ноль изображений
против медианы 3–4 и заполнение 0,23. У ВСЕХ двадцати в первом экране
есть зрительный объект — либо плотный набор (obys 1201 узел), либо
полноэкранный материал (locomotive, resn, lusion). У нас не было ни
того, ни другого, и читалось это как «не стильно»: смотреть было не
на что. Второе поле заводить нельзя — смысл в том, что материал один.

**Замер движения важнее счёта анимаций.** Три захода подряд чинили не
ту вещь: по преобразованию при прокрутке Atlas давал 491 при медиане
330, то есть движения было БОЛЬШЕ нормы. Прежде чем добавлять
анимацию, прогоняется `research/05_MOTION.md` — там метрика и её
слепое пятно (геометрия не видит холст, для него есть пиксельный
замер).

**Инверсий на полосе ровно три, и это ритм, а не материал:** средний
такт манифеста (единственное отрицание — «ваш интернет тут ни при
чём»), лента фактов между большими сценами и финальный блок. Каждая —
чёрная плита с белым набором; на плите инверсия переворачивается
обратно (белая кнопка, чёрный текст). Четвёртую заводить нельзя:
переворот работает, пока он событие.

**Наведение переворачивает материал, а не подкрашивает его.** Цвет
означает «измерено», поэтому отклик на курсор может быть только
инверсией — строка тарифа и ячейка состава на `:hover` становятся
чёрными плитами.

**Пара «залитое + контурное».** Вторая строка первого экрана набрана
обводкой (`-webkit-text-stroke`), первая — плашкой: один материал
показан с двух сторон, без единого цвета и без единого объекта.
Правило закрыто `@supports` намеренно: без поддержки обводки
`color: transparent` оставил бы пустое место вместо слова. Контур
заливается на наведение и по мере ухода первого экрана.

**Линза-инвертор** — `src/components/graticule/InvertLens.tsx`.
Курсор не подменяется: системный остаётся на месте, сверху едет слой
с `mix-blend-mode: difference`, который переворачивает материал под
собой. Это тот же жест, что у кнопки и у ленты фактов, привязанный к
руке. Один слушатель на документ, значение считает rAF, перерисовки
React нет. На грубом указателе и при `prefers-reduced-motion` слой не
создаётся вовсе.

**Закреплённая горизонтальная сцена** — состав подписки едет вбок,
пока читатель проходит высоту секции. Это не перехват прокрутки: кадр
держит `position: sticky`, сдвиг считает шкала прокрутки секции. На
телефоне приём выключен — там уже есть лента со scroll-snap, и две
горизонтали в одном месте спорят.

**Полоса прочтения** считает `animation-timeline: scroll(root block)`
— ни слушателя, ни rAF.

**Один холст на сайте** — `src/components/graticule/SignalTrace.tsx`.
Рисует не абстрактную рябь, а длительность кадров браузера на
устройстве читателя; показание живёт шестой ячейкой приборной полосы.
Цикл встаёт, когда вкладка скрыта или первый экран ушёл из кадра; при
`prefers-reduced-motion` не запускается вовсе. Второй холст заводить
нельзя: смысл приёма в том, что прибор один.

**Мост к чернильной системе.** Шапка, футер и часть сцен написаны на
токенах старого слоя (`.b-*`), и они одни на все страницы. Мост живёт
в `graticule.css` и объявлен на `body:has(.g)`, а НЕ на `.g`:
наложения (согласие на cookie, баннер установки, предложение passkey)
живут в корневом layout рядом со страницей, а не внутри неё.
Селектор `.g, body:has(.g)` писать нельзя — оптимизатор CSS склеивает
соседний блок `.g { … }` с ним и теряет второй селектор.

Токены системы объявлены на `:root`, а не внутри `.g`. Причина
измерена дважды: значение, объявленное ниже тела по дереву, не
разрешается в правиле на теле, и переменная становится не
«унаследованной», а ПУСТОЙ — так пропадал фон страницы, а потом фон
карточки согласия на cookie. Класс `.g` остаётся включателем корпуса
(фон, чернила, гарнитура), а не хранилищем значений.

**Motion.** Всё нативное, ноль библиотек: `animation-timeline: view()`,
`timeline-scope`, `@property` для бегущих чисел. На домашней странице
59 анимаций, 49 из них считает шкала прокрутки, 2 холостых.

**ВЕСЬ МОУШН ГЛАВНОЙ ЖИВЁТ В ОДНОМ РАЗДЕЛЕ** — `graticule-home.css`,
раздел 12. Выше этой строки анимация не объявляется. Раздел разбит на
пять частей: базовые состояния (без скрипта страница отрисована в
конечном виде), приёмы по прокрутке одним `@supports` с нумерацией
№1–№14, холостой слой, отклик на действие, упрощение движения. Если
приём приходится писать в разделе сцены — это не приём, а костыль.

Файл пересобран целиком по этой причине: прежний вырос наслоениями до
1541 строки, десяти отдельных блоков `@supports` и тринадцати классов
от заходов, которых больше нет в разметке. Найти в нём, что именно
движется, было нельзя — значит, нельзя было и отвечать за движение.

**Холостого движения ровно два:** лента фактов и мигание живых
показаний. Обосновано замером: у 14 сайтов из 20 покой нулевой,
«страница дышит сама» не условие жанра (`research/05_MOTION.md`). Всё
остальное отвечает на прокрутку или на руку.

Ключевые механики, каждая оплачена ошибкой:
- Диапазон буквы задаётся `animation-range-start: entry calc(8% +
  var(--i) * 1.6%)`. Имя фазы стоит СНАРУЖИ `calc()`, проценты внутри;
  обратный порядок браузер отбрасывает целиком.
- `@property --lap-n` объявлено `inherits: true`: счётчик печатается в
  `::after`, и при `inherits: false` псевдоэлемент получал начальное
  значение и показывал «0%» при любом положении прокрутки.
- Две силы на одном элементе (собственный ход + прокрутка)
  объявляются одним списком `animation-name`, иначе правило холостого
  слоя перебивает имя целиком.
- Отступ бегущей строки живёт ВНУТРИ дорожки: сдвиг на −50% верен
  только тогда, когда обе копии одинаковой ширины.
- Состояния, которые прячут контент до срабатывания скрипта,
  объявляются под `.px-js`. Без скрипта страница отрисована целиком.
- `prefers-reduced-motion` упрощает слой, а не ломает его.

**Живые взаимодействия** — `src/components/pixel/effects.tsx`
(`Magnetic`, `Scramble`, `SplitText`, `SpotlightLayer`, `useTilt`,
`useGridTorch`, `PixelTrail`, `PixelDissolve`, `useScrollScene`,
`useMouseLayer`, `usePixelBurst`, `RollingNumber`). Правила те же:
только `transform`, `opacity` и CSS-переменные, значение считает rAF.

**Кастомного курсора нет.** `cursor: none` на `body` не ставит ни один
из восемнадцати разобранных сайтов, а у нас он однажды убил курсор на
всём сайте.

**Логотип не меняется:** формы в `src/components/pixel/BrandMark.tsx`
взяты один в один из `src/app/icon.tsx`.

**Формы** — общий слой `.px-field` / `.px-label` / `.px-input` /
`.px-choice` в `globals.css`. Кегль поля на телефоне 16px не по
эстетике: при меньшем Safari на iOS увеличивает страницу при фокусе.
Проверка на клиенте и по каждому полю отдельно, ошибка живёт рядом со
своим полем (`aria-describedby`, `aria-invalid`), фокус уходит на
первое неверное. Служебные английские строки от API наружу не
показываются. `user-scalable` и `maximum-scale` из viewport убраны
(WCAG 1.4.4).

**Метаданные страницы.** Свой `title` и описание страница объявляет

## Conventions for AI Assistants

- Brand: **Atlas Secure**
- All UI text: **Russian**
- **Два языка продукта.** Публичные страницы — это «ускоритель
  интернета»: скорость, стабильность, отсутствие просадок. Названия
  туннельных протоколов там не употребляются.
- **Аббревиатура на витрине — VPS, а не VPN** (решение владельца от
  8 сентября 2026). Содержание текстов при этом прежнее: шифрование,
  смена страны, доступ. Меняется слово, а не смысл. Слово «VPN» на
  публичных страницах, в описании сайта, ключевых словах и
  structured data не употребляется.
  Оговорка, которую нужно держать в голове при написании текстов:
  VPS — общепринятое имя виртуального сервера, а выделенные серверы
  продаются тут же, на `/vds`. Поэтому ускоритель называется всегда
  «VPS-ускоритель», с уточнением, а серверы — «выделенные серверы»
  и «VDS», и никогда не «VPS».
- **Инженерных терминов на витрине нет.** «Магистраль» заменена на
  «ширину канала» с бытовым объяснением, «аптайм» — на «время без
  сбоев». Термин, который приходится объяснять покупателю, на
  публичной странице не работает.
- **Экраны только для вошедших** (кабинет, `/add-device`, `/subscribe`,
  шаг установки с ключами на `/devices` при сессии) — слова «VPN» и
  «обход» можно и нужно использовать для ясности (владелец, 13.09.2026):
  «Ключ 1 · Основной VPN» и «Ключ 2 · Обход». Всё, что видит гость или
  поисковик (витрина, `/devices` без сессии, metadata, structured
  data) — по-прежнему без «VPN» и «обход»: «Основной» / «Усиленный»,
  «Пакеты трафика».
- **Автосписаний нет**: оплата разовая за выбранный срок, кнопки
  «отменить подписку» в кабинете нет. Писать «отмена в один клик»
  нельзя — только «без автосписаний» / «продлеваете, когда сами решите»
  (разбор продажника 12.09.2026, COMPLIANCE-CHECK.md).
- **Пакеты трафика** (в кабинете и боте — «Обход», bypass-сущность
  панели без срока, лимит в ГБ, покупки складываются) — отдельный
  продукт; цены только из `src/lib/traffic-packs.ts` (владелец,
  13.09.2026). На витрине — «Пакеты трафика». К пробному периоду —
  500 МБ обхода. При связке бот↔сайт остатки ГБ складываются в ключ
  обхода бота, премиум — остаётся ключ с большим сроком, +7 дней за
  связку один раз. Сквад обхода — `6947418d-83b6-4050-a10c-3829e4cd4b2c`
  (по умолчанию `REMNAWAVE_BYPASS_SQUAD_UUID`, тот же, что у бота),
  лимит устройств обхода — 5.
  **Как устроено (13.09.2026):** витрина — раздел «Пакеты трафика» на
  `/pricing` (`#traffic`); оплата — `/subscribe?product=traffic&pack=gbN`
  → `POST /api/payments/create {product:"traffic", packId}` (сумма только
  с сервера; `payments.product/traffic_pack_id/traffic_bytes`, plan =
  'traffic', period = 0). `confirmPayment` пишет в журнал `bypass_grants`
  (`payment:<id>`, в той же транзакции; премиум не продлевается), затем
  `src/lib/bypass-grants.ts` прибавляет ГБ в панели: сущность связанного —
  ботовская `{telegram_id}`, иначе сайтовая `ST…_bp` (создаётся первой
  покупкой или пробным периодом; тег `SITE_BYPASS`, 2099, `NO_RESET`);
  прибавка — read-modify-write через `bypass_traffic_ops`, панель
  недоступна — долг, повторяет воркер. Пробные 500 МБ — `trial:<id>` в
  транзакции пробного (`store.getOrCreateUser`). Возврат — пометка + письмо,
  ГБ не снимаются. Кешбэк рефереру — как с любой оплаты. Админ — «Начислить
  ГБ» (`admin:<requestId>`, идемпотентно). Кабинет не ждёт панель:
  `/api/user/subscription` — только БД (ссылка ключа 2 кешем
  `users.bypass_subscription_url`), остаток — `GET /api/user/bypass` после
  отрисовки. Два ключа везде подписаны одинаково — `src/lib/key-names.ts`
  (гостю «Основной» / «Усиленный», вошедшему «Основной VPN» / «Обход»).
- Trial: **3 дня** (`TRIAL_DURATION_DAYS` в `src/lib/remnawave.ts`)
- Referral: **только кешбэк** на баланс с оплат приглашённых — 10%, с 25
  оплативших — 25%, с 50 — 45% (`getLoyaltyTier`, `src/lib/store.ts`).
  «+20 дней» не обещать — снято владельцем 12.09.2026.
- Возвраты денег — вручную через поддержку; сайт по `refund.succeeded`
  только помечает платёж и уведомляет админа, дни не снимает.
- Telegram bonus: **+7 дней**
- Никогда не коммитить `.env` — только `.env.example`
- Иконки — только собственный набор `src/components/pixel/Icon.tsx`.
  Никаких сторонних библиотек, эмодзи и стоковых иллюстраций.
- Сессия — httpOnly cookie (`session` = user id)
- **Числа на страницах должны быть подтверждены кодом.** Список
  поддерживаемых платформ — `src/app/devices/page.tsx`, цены —
  `src/lib/plans.ts`, длительность триала — `src/lib/remnawave.ts`.
  Заявления, которые нельзя проверить (сертификации, число
  пользователей), помечаются в файле как требующие подтверждения.
- Перед сдачей страницы: сборка, `tsc`, проверка на 320/375/414/768/
  1024/1280/1440/1920 — без бокового скролла, без тап-зон меньше
  44px, без непоявившегося контента и ошибок консоли.
